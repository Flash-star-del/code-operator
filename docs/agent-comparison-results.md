# 双系统横评结果摘要：code-operator vs Kimi Code

本摘要是对正式九单元 Track A 运行（2026-09-02）的能力解读层。原始报告
`docs/evidence/agent-comparison-track-a-9.json`（SHA-256
`dea849aadfe2603f2dbb008589395bb931bf6189532a561960a5997eb499f5ce`）包含预注册
manifest（SHA-256 `66cf45ea705bf6b1ac76e409b961eca46b9465c76816c291bacd296278fe901a`）
下全部三个系统的九个单元，本摘要不修改、不删除任何原始数据。

## 方法（一段话）

三个冻结的合成 Python 任务（T1 区间合并 / T2 重试退避 / T3 事件分级），每个
系统-任务组合运行一次，严格串行、单元上限 360 秒、不重试。评分与被测系统完全
独立：全新 Git 工作区 + 隐藏测试（F2P/P2P）+ 文件范围检查；CLI 事件遥测不参与
评分。缓存产物（`__pycache__` 等）不计入变更。

定性观察（样本极小，仅描述本批运行）：

- 两系统在 T3 上改动了完全相同的文件集与行数足迹（`events.py` + `levels.py`，
  +14/−4），在 T2 上都自主添加了回归测试文件（任务允许范围内）——解题路径高度相似。
- Kimi Code 的补丁一致更小（T1 仅 +1/−1 的最小修复），平均耗时约为 code-operator
  的 63%。
- code-operator 唯一的失败模式是工程习惯问题：倾向创建临时验证脚本且未清理，
  三次独立运行（Pilot 尝试 3、5 与正式 T1）均复现，具备可复现性；其通过的任务
  中隐藏测试全绿。

## Claude Code 数据的处理说明（透明排除）

正式运行中 claude-code 的三个单元均在 6.2–6.4 秒内退出、零文件改动、近零
token——与同日早前 Pilot（曾 58.2 秒正常解出 T1）矛盾，符合运行窗口内产品侧
API 故障特征。按冻结协议这三个单元如实记为 FAIL 并完整保留在原始报告与计划文档
中；但由于无法区分"产品能力"与"当时的服务故障"，本摘要不将其纳入能力对比。
排除决定本身在此公开声明，可供复核。

## code-operator 相对缺陷分析（基于全部留存运行的交叉证据）

以下缺陷从正式运行与各次 Pilot 的留存报告中交叉提取。Pilot 块按协议不是能力
结果，此处仅作为行为模式**可复现性**的辅助证据引用。

**D1 — 范围纪律不稳定（唯一正式失败的直接原因）。** T1 的四次留存运行中，
三次残留自建临时验证脚本（尝试 3：`_verify_edge.py`+`_verify_edge_test.py`；
尝试 5：`_check_ranges_tmp.py`+`tests/_tmp_edge_check.py`；正式：
`_verify_ranges.py`），一次干净且最小（尝试 4：仅 `ranges.py` +1/−1，21.5 秒
resolved）。模式明确：倾向写"草稿验证脚本"辅助推理，但缺少收尾清理步骤，
且该行为不稳定出现。Kimi Code 同期所有运行零违规。改进方向：在循环收尾
增加工作区自检/清理阶段，或在系统提示中约束草稿文件生命周期。

**D2 — 退出码语义缺陷（本横评新发现的产品 bug）。** `resolved=True` 却返回
退出码 1 的组合出现两次（尝试 4 的 T1、正式的 T3），而正式 T2 正常返回 0
（`COMPLETED`）；观察到的五次运行中四次以非零码退出。退出码不反映任务结果，
会误导脚本化调用与 CI 集成。成因待查（疑与收尾路径或轮次上限判定有关），
应作为独立缺陷修复。Kimi Code 全部正常退出 0。

**D3 — 补丁不够最小。** 同一 T1 修复，Kimi Code 稳定 +1/−1；code-operator
除尝试 4 外为 +32～+49（含违规脚本行数）。T2 两系统都在允许范围内添加了回归
测试，code-operator 的补丁仍为 Kimi 的 4 倍（+44 vs +11）。T3 两者完全一致
（+14/−4）。倾向：过度生成辅助代码而非最小修复。

**D4 — 耗时更长且方差大。** T1/T3 上耗时约为 Kimi 的 2 倍（151–186.8s vs
65.5–91.6s；122.4s vs 62.2s），且跨运行方差大（T1 从 21.5s 到 186.8s）；但
T2 上反而更快（92.0s vs 102.9s），并非全面劣势。

平衡起见：code-operator 通过的任务全部隐藏测试满分，T3 与 Kimi 的解完全同构，
失败集中于工程习惯（D1）而非补丁能力；D1、D2 均已有可复现证据，可直接转化为
后续修复项。

## 局限与后续工作

单次运行、三个合成任务，不构成统计结论，不计算显著性或置信区间，不可与官方
SWE-bench 比较。科研级版本需要：每组合多副本、更大且更多样的任务集、故障系统的
根因隔离与重测、以及跨运行窗口的重复。
